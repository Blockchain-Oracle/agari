## Event book

Every order is `BUY_YES`, `SELL_YES`, `BUY_NO` or `SELL_NO`, priced in YES ticks. The book supports a direct Yes or No trade, minting a complete Yes/No pair when both sides buy, and burning a pair when both sell. PostOnly can rest before a Window opens; a taker cannot fill it until trading starts. IOC takes available size and cancels the rest; FOK requires a complete fill.

A Window moves Listed → Trading → Locked → Resolved or Voided. The closing signed print at or above the opening print pays Up, including ties. A void returns the stake as credit rather than guessing an outcome. [First call](/trading/first-trade) covers the user journey.

## Trading Balance and desk

`agari-vault` holds devnet tUSDC and enforces a user's session grant with spending, daily and open-position limits. `agari-desk` is a different program: a mainnet desk PDA would hold USDC and PreStocks under allowed-name, cap, reference, premium, output-floor and withdrawal checks. Its [rehearsal and current limit](/architecture/desk) must not be confused with a live mainnet deployment.
